# 플래시 대비 계층화 저장 설계 — 총소유비용 비교 분석

**접속기록 2년 보관 의무가 있는 환경에서 보안 로그 저장 비용을 어떻게 줄일 것인가.**

데이터 감축과 계층화 중 어디에 투자해야 하는지를 판단하는 계산 도구이며, 동시에 그 판단에 이르기까지의 사고 과정을 기록한 분석입니다.

| 항목 | 내용 |
|---|---|
| 기간 | 2026년 9월 4일 ~ 9월 6일 |
| 단계 | Phase 0 ~ 10 (전부 완료) |
| 산출물 | 문서 11건, 계산 모듈 10개, 검증 288건, 차트 4장 |
| 성격 | 결정론적 총소유비용 모델링. 시계열 예측 배제 |

---

## 1. 배경

### 1.1 시장 조건의 변화

2025년 이후 플래시와 대체 계층의 용량당 단가 격차가 급격히 확대되었습니다.

| 시점 | 플래시 대비 디스크 단가 격차 |
|---|---|
| 2025년 2분기 | 4.9배 |
| 2026년 1분기 | 23.2배 (정점) |
| 2026년 3분기 | 18.6배 |

주요 원인은 세 가지입니다.

1. **NAND 계약가 급등.** 2026년 1분기에 전분기 대비 33~38% 상승했고, 엔터프라이즈 SSD 계약가는 같은 기간 약 80% 상승했습니다.
2. **상승세의 지속.** 2026년 2분기에는 NAND 계약가가 70~75% 추가 상승하여 이번 주기에서 처음으로 DRAM 상승률을 앞질렀습니다.
3. **공급 측 구조 변화.** 니어라인 디스크 제조사가 생산 능력을 확대하지 않기로 결정하면서 대체 계층의 조달 여건도 함께 악화되었습니다.

### 1.2 이 분석이 착수된 이유

단가 격차가 벌어지면 **저장 설계의 최적해가 이동할 가능성**이 있습니다. 그러나 다음 두 가지가 확인되지 않은 상태였습니다.

1. 격차가 얼마나 벌어져야 설계를 바꿀 만한가
2. 그 판단이 어떤 조건에서 뒤집히는가

**선행 분석**([SIEM 자체 구축 대비 구매 총비용 비교](https://github.com/eugeejo-ui/siem-build-vs-buy-tco))에서 구축한 계산 엔진의 구조와 검증 방식을 승계했습니다. 다만 원장 스키마가 다르고 단위계 분리가 새로 필요하여 모듈은 전면 재작성했습니다.

## 2. 현황 분석

### 2.1 대상 환경

| 항목 | 값 | 근거 |
|---|---|---|
| 업종 | 국내 중견 이커머스 | — |
| 보관 의무 | 접속기록 2년(730일) | 개인정보의 안전성 확보조치 기준 제8조 |
| 일일 로그량 | 입력 변수 (추정하지 않음) | 조직마다 상이 |
| 현재 구성 | 전량 고성능 계층 보관 | — |

### 2.2 저장 계층의 구조

로그 시스템은 데이터를 두 형태로 보관합니다.

| 형태 | 구성 | 원본 대비 비중 |
|---|---|---|
| 검색 가능 상태 | 원본 + 검색 색인 | **0.50** |
| 아카이브 상태 | 원본만 (색인 제거) | **0.15** |

**검색 색인이 저장량의 70%를 차지합니다.** 원본은 이미 압축되어 원래 크기의 15%로 줄어 있으나, 그 위에 붙는 색인이 35%를 추가로 점유합니다.

### 2.3 가격 자료의 신뢰도 문제

착수 직후 가격 자료에 문제가 있음을 확인했습니다.

1. **단일 지수가 같은 분기에 세 가지 배수를 동시 발표합니다.** 2026년 1분기에 대해 16.4배, 22.6배, 23.2배가 각각 제시되었으며, 비교 대상(광의 평균, TLC 30TB, QLC 30TB)이 달라 발생한 차이입니다.
2. **발행처가 자사 과거 수치를 사후 개정했습니다.** 2026년 1분기 TLC 가격을 1월 발표 시 $10,950으로 제시했다가 6월 갱신에서 $17,500으로 상향했습니다.
3. **발행처가 하이브리드 스토리지 벤더입니다.** 자체 발행 지수이므로 편향 가능성을 배제할 수 없습니다.

**따라서 특정 값을 신뢰하지 않는 설계가 필요했습니다.** 이 판단이 이후 방법론 전체를 규정했습니다.

## 3. 문제 정의

### 3.1 착수 시 질문

> **"플래시와 대체 계층의 단가 격차가 벌어진 지금, 두 레버 중 어디에 투자해야 하는가. 그리고 그 답은 몇 배에서 뒤집히는가."**

두 개의 레버를 비교 대상으로 설정했습니다.

| 레버 | 작동 방식 | 조작 변수 |
|---|---|---|
| A. 데이터 감축 | 동일 계층 내에서 물리 점유량 축소 | 감축률 |
| B. 계층화 | 저단가 계층으로 데이터 이동 | 즉시 검색 기간 |

### 3.2 방법론 선언 — 예측하지 않습니다

**결정론적 총소유비용 모델링을 채택하고 시계열 예측을 명시적으로 배제했습니다.**

가격을 예측하는 대신 **스캔 축**으로 다룹니다. 관측된 배수의 하한과 상한을 구간으로 잡고 그 내부를 훑습니다. 근거는 두 가지입니다.

1. **결과물의 수명.** 특정 시점의 가격 전망은 그 시점이 지나면 폐기됩니다. 반면 "배수 몇 배에서 판단이 뒤집히는가"는 가격이 변동해도 유효합니다.
2. **2.3절의 신뢰도 문제.** 어느 값을 고르든 그 선택이 곧 결론이 되는 상황을 회피할 수 있습니다.

이 설계는 이후 네 차례 검증되었습니다.

| 시점 | 확인 내용 |
|---|---|
| Phase 2 | 지수 세 계열이 동시 존재하고 과거 수치가 개정된 사실 확인 |
| Phase 4 | 플래시 단가를 배수로부터 생성하여 지수 선택이 결론에 무관해짐 |
| Phase 6 | 손익분기가 아카이브 단가·프리미엄·로그량과 무관함을 수치로 확인 |
| Phase 10 | 대표값 미설정 상태가 유지되는지를 자동 검사로 고정 |

### 3.3 범위에서 제외한 항목

산정 근거를 확보하지 못한 항목은 계산에 넣지 않고 제외 사실을 문서에 남겼습니다.

| 제외 항목 | 사유 | 후속 처리 |
|---|---|---|
| 1. 전력·랙 공간·냉각 | 국내 데이터센터 전력 단가 조사가 별도 작업 단위를 형성 | 후속 과제 |
| 2. 성능(IOPS·지연) | 금액 환산 근거 없음 | 정성 서술 |
| 3. 유지보수·설치 인건비 | 벤더별 편차가 크고 공개되지 않음 | 결과를 매체 원가 비교로 한정 표기 |
| 4. NAND 가격 예측 | 방법론 선언에 따름 | 배제 |
| 5. 제품 간 성능 벤치마크 | 아키텍처 선택 문제이며 제품 비교가 아님 | 배제 |

## 4. 가설 설정

### 4.1 가설 H1 — 전환점의 존재

> 감축이 제공하는 이득의 상한은 나눗셈 6이다. 계층화가 제공하는 이득은 나눗셈 R(관측치 약 22)이다. 따라서 R이 커질수록 계층화가 감축을 압도하며, **그 사이에 전환점이 존재한다.**

### 4.2 가설 H2 — 두 레버의 상쇄

> 두 레버는 곱해지지 않고 서로 상쇄한다. 데이터의 70%를 계층화하면 감축률 개선의 효과는 잔여 30% 구간에만 적용되므로 절대 이득이 감소한다.

### 4.3 반증 조건 — 착수 전에 기록

**결과가 나온 뒤에 가설을 수정하는 것을 방지하기 위해 반증 조건을 착수 전에 명시했습니다.**

> 계층화 가능 비율이 낮은 구간, 즉 전 기간 즉시 검색이 요구되는 워크로드에서는 감축이 이긴다. **이 구간이 실제로 존재하지 않으면 H1은 자명한 결론이 되어 분석의 가치가 하락한다. 그 경우에도 결과를 그대로 보고한다.**

## 5. 가설 검증

### 5.1 검증 구조

```
[입력] 일일 로그량 → 계층별 논리 용량 → 감축 → 오버헤드 → 물리 용량 → 단가 → 총비용
                                                                        ↓
                                                        손익분기 탐색 → 민감도·불확실성
```

**적용 순서가 중요합니다.** 감축을 오버헤드보다 먼저 적용합니다. 저장 장비가 기록 시점에 감축을 수행하고 그 결과에 대해 패리티가 생성되기 때문이며, 순서를 바꾸면 물리 용량이 과소 산정됩니다.

### 5.2 가설 H1 — 부분 반증

| 구성 | 전환점 | 관측 범위(3.0~30.0) 내 |
|---|---|---|
| 단일 사이트 | **존재하지 않음** (탐색 범위 1.0~50.0 전 구간에서 계층화 우세) | — |
| 다중 사이트 | 1.731배 | ❌ 범위 밖 |

**반증의 내용은 다음과 같습니다.**

| 단가 격차 | 전량 고성능 | 최대 계층화 |
|---|---|---|
| **1배 (동일 단가)** | 1.23백만원 | **0.49백만원** |
| 22배 (관측 시장) | 89.3백만원 | 1.8백만원 |

**플래시와 아카이브의 단가가 같아도 계층화가 유리합니다.**

> **계층화의 이득은 단가 격차에서 오지 않습니다. 색인 제거(0.50 → 0.15)에서 옵니다.**
> **단가 격차가 벌어진 것은 그 이득을 키웠을 뿐, 계층화를 유리하게 만든 원인이 아닙니다.**

### 5.3 가설 H2 — 지지, 정량 확인

색인 감축률을 1.00에서 6.00으로 개선했을 때의 절대 절감량입니다.

| 즉시 검색 기간 | 절감량 | 총량 대비 |
|---|---|---|
| 730일 (계층화 없음) | **32.70 TB** | 58.3% |
| 90일 | 4.03 TB | 20.5% |
| 30일 (강한 계층화) | **1.34 TB** | 8.2% |

**계층화를 강하게 할수록 감축 개선의 절대 효과가 24배 줄어듭니다.** 아카이브 계층에는 색인이 없어 감축 개선이 적용될 대상 자체가 존재하지 않기 때문입니다.

### 5.4 반증 구간의 확인

반증 구간은 **실재했습니다.** 다만 그 구간을 만든 것은 당초 예상했던 데이터 접근 요구가 아니라 **가용성 요건(사이트 수)**이었습니다.

| 즉시 검색 기간 | 단일 사이트 물리 용량 | 3사이트 물리 용량 |
|---|---|---|
| 730일 | 36.44 TB | 36.44 TB |
| 90일 | 17.29 TB | **59.79 TB (증가)** |

**다중 사이트 구성에서는 계층화가 물리 용량을 오히려 증가시킵니다.** 아카이브 오버헤드 5.76배가 색인 제거 이득을 압도하기 때문입니다.

## 6. 검증 과정에서 알게 된 것

**착수 시 예상하지 못했던 결과 18건 중 서술의 중심이 되는 여섯 가지입니다.**

### 6.1 제조사 감축 보증은 이 워크로드에서 도달할 수 없습니다

제조사 약관 원문을 확보해 확인했습니다.

> Unreducible Data의 예에는 **호스트에서 압축된 데이터**, 호스트에서 암호화된 데이터, 오디오·이미지·PDF·비디오 파일이 포함된다.

로그 원본은 이미 압축된 상태로 저장 장비에 도달하므로 **계약상 보증 대상이 아닙니다.**

```
혼합 감축률 = 0.50 / (0.15 + 0.35 / d)
→ 색인이 0바이트가 되는 물리적 불가능 경우에도 0.50 / 0.15 = 3.33이 상한
```

**보증 배율 6:1은 물리적으로 도달할 수 없습니다.** 확인 과정에서 다음 사실도 함께 드러났습니다.

1. 보증 배율은 제품군별로 3배, 5배, 6배로 상이합니다.
2. 물리 용량의 50% 이상이 기록되기 전에는 보증이 발동하지 않습니다.
3. 미달 시 구제 방식은 현금 배상이 아니라 튜닝 또는 하드웨어 추가이며, 제품당 1회로 제한됩니다.

### 6.2 시장 지수의 디스크 계열이 제조사 공시와 모순됩니다

지수 발행처가 단일 벤더이므로 독립 출처로 교차검증했습니다. **제조사의 SEC 제출 서류에서 출하 엑사바이트를 확인해 TB당 실현 단가를 직접 도출**했습니다.

| 항목 | 시장 지수 | 제조사 공시 도출값 |
|---|---|---|
| 1년 상승률 | +146% | **보합~소폭 상승 (분기 2.6%)** |
| TB당 단가 | $16.5 → $40.5 | **$13.5 ~ $14.9** |

**절대 단가가 약 3배 차이 나고 상승률의 크기가 전혀 다릅니다. 디스크 계열은 채택하지 않았으며, 코드가 이를 강제합니다.**

반면 플래시 계열은 계약가 조사 누적치(4.1~5.1배)와 지수 발표치(6.5배)의 방향이 일치하여 채택했습니다.

### 6.3 어레이 정품 드라이브는 시장 시세의 3배입니다

국가종합전자조달시스템에서 **금액과 용량이 함께 명시된 낙찰 자료 4건**을 확보했습니다.

| 출처 | 플래시 TB당 단가 |
|---|---|
| 시장 지수 (30TB TLC) | $753 |
| 소매 신품 NVMe | $300 ~ 1,172 |
| **국내 조달 어레이 정품** | **$2,115 ~ 2,957** |

**고객이 실제로 지불하는 플래시 가격은 NAND 시세가 아니라 어레이 벤더의 드라이브 단가입니다.** 시장 지수를 그대로 모델에 투입하면 실제 견적보다 약 3배 낮게 산정됩니다.

이 값은 **독립 경로로 교차검증되었습니다.** 소매 매체가에 배수(22)와 정품 프리미엄(3.3)을 곱해 계산한 2,450,976원/TB이 국내 조달 실거래 하한 2,856,538원/TB과 **14% 차이**로 일치했습니다.

또한 낙찰 금액이 **제조사 공급 협약가의 99.7~99.8%**였습니다. 유통 마진이 0.2~0.3%에 불과하므로 이 단가는 협상으로 낮추기 어렵습니다.

### 6.4 감축과 패리티가 서로를 상쇄해 순 효과가 사라집니다

| 값 | 출처 |
|---|---|
| 혼합 감축률 | **1.538** (로그 플랫폼 저장 계수 + 색인 감축률 2.00) |
| 블록 RAID 오버헤드 | **1.536** (국내 조달 규격서) |

**서로 다른 두 출처에서 독립적으로 나온 값이 소수 셋째 자리까지 일치합니다.**

두 값은 정반대 방향으로 작동합니다.

1. **감축은 논리 용량을 1.538로 나눕니다.** 저장 장비가 압축과 중복 제거로 데이터를 줄입니다.
2. **패리티는 그 결과에 1.536을 곱합니다.** 디스크 고장에 대비한 복구용 데이터가 추가됩니다.

```
논리 4.50 TB → 감축(÷1.538) → 2.92 TB → 패리티(×1.536) → 물리 4.49 TB
```

**감축률 1.538을 확보했음에도 물리 용량이 논리 용량과 사실상 동일합니다.** 순 효과가 1.00에 수렴합니다.

**적용 순서가 이 관계를 만듭니다.** 저장 장비는 감축된 결과에 대해 패리티를 생성합니다. 순서를 바꾸면 패리티까지 감축 대상으로 세게 되어 물리 용량이 과소 산정됩니다.

**다만 이는 색인 감축률을 2.00으로 가정했을 때만 성립하는 우연입니다.**

| 색인 감축률 | 혼합 감축률 | 순 효과 |
|---|---|---|
| 1.00 | 1.000 | 1.536배 증가 |
| **2.00 (기준값)** | **1.538** | **0.999배 (상쇄)** |
| 6.00 | 2.400 | 0.640배 감소 |

기준값 2.00에는 근거가 없습니다(7.2절 참조). 따라서 이 상쇄를 일반 법칙으로 제시하지 않으며, **감축 효과를 오버헤드와 분리해 평가하면 안 된다는 사례로만 인용합니다.**

> **감축률 1.538을 확보했다는 사실만 보면 용량이 35% 줄어든 것으로 오인하게 됩니다. 실제로는 0.1%도 줄지 않았습니다.**

### 6.5 최적화가 대응 여력을 소진합니다

3사이트 분산을 같은 예산으로 수용하려면 배수가 얼마 이상이어야 하는지 산출했습니다.

| 현재 즉시 검색 기간 | 수용에 필요한 최소 배수 |
|---|---|
| 365일 | 3.06배 |
| 180일 | 5.82배 |
| 90일 | 11.30배 |
| 60일 | 16.84배 |
| **30일** | **33.84배** |

**직관과 반대입니다.** 계층화를 잘해둔 조직이 더 유리할 것으로 보이나 그렇지 않습니다.

**이유는 여력의 부재입니다.** 30일까지 줄여둔 조직은 더 줄일 구간이 1일까지밖에 남지 않았고, 그 절감 폭이 오버헤드 증가를 상쇄하지 못합니다. 반면 365일을 유지하던 조직은 아직 줄일 구간이 많이 남아 있습니다.

> **저장 설계를 이미 최적화해둔 조직일수록 가용성 요건 추가를 감당하기 어렵습니다.**

![3사이트 도입 시 유지 가능 기간](outputs/figures/fig3_equivalent_days.png)

같은 구조가 복제 구성에서도 확인되었습니다. **사본을 여러 벌 두는 조직일수록 3사이트 요건을 쉽게 수용합니다.** 복제로 고성능 계층이 커지면 계층화로 줄일 수 있는 몫도 함께 커지기 때문입니다.

### 6.6 점 추정값의 크기가 판정의 확실성을 보장하지 않습니다

**본 분석의 방법론에 관한 결론입니다.**

계산에 사용한 값 중 일부는 실측이 아니라 범위 추정입니다. 그 불확실성을 반영해 반복 계산한 결과입니다.

| 즉시 검색 기간 | 점 추정 임계값 | 시장(22배)과의 차이 | **수용 가능 확률** |
|---|---|---|---|
| 30일 | 33.84배 | 54% 초과 | **51%** |
| 60일 | 16.84배 | 24% 여유 | 87% |
| 90일 | 11.30배 | 49% 여유 | **100%** |

**30일 기준은 임계값이 시장 배수를 54% 웃돌아 판정이 확실해 보입니다. 그러나 임계값 자체가 10.8에서 50.1 사이에서 흔들리며, 중앙값 19.3은 시장 배수보다 낮습니다.**

점 추정과 중앙값이 서로 반대 방향을 가리키므로 확률이 51%로 산출됩니다.

![불확실성 구간](outputs/figures/fig4_uncertainty.png)

**점 추정만 제시했다면 근거 없는 확신을 전달했을 것입니다.**

## 7. 한계점

### 7.1 계산이 유효하기 위한 조건

**비용이 아니라 가능 여부의 문제이므로 계산으로 답할 수 없는 항목입니다.**

#### 조건 1 — 아카이브 매체를 조달할 수 있을 것

| 확인 사항 | 내용 |
|---|---|
| 제조사 생산 배분 | 주요 2개사 모두 2026년 물량 배분 완료. 2027년 상반기 주문을 접수 시작하는 단계 |
| 납기 | 수 주에서 **52주 이상**으로 확대 |
| 생산 능력 확대 | 계획 없음. 대용량 제품으로만 성장 |
| 제조 리드타임 | 12~18개월 |

**시장조사기관은 제조 능력이 대형 클라우드 사업자에 우선 배분되면서 중견 규모 기업 시장이 영향을 받을 것으로 보고 해당 시장 전망을 하향 조정했습니다.** 본 분석의 대상이 그 시장에 해당합니다.

#### 조건 2 — 경계 밖 데이터에 즉시 조회 요구가 없을 것

**아카이브 계층의 데이터는 검색되지 않습니다.** 이는 "느리다"가 아니라 "조회되지 않는다"는 뜻입니다.

조회하려면 다음 절차가 필요합니다.

1. 시각 범위로 해당 데이터 묶음을 식별
2. 복원 영역으로 복사
3. 색인 재생성 명령 실행

**명령줄 수동 작업이며, 복원된 데이터는 보존 정책 대상에서 제외되어 수동 삭제가 필요합니다.**

> **경계 밖 데이터가 필요해지는 순간, 그것은 조회가 아니라 복구 작업입니다.**

### 7.2 근거가 약한 항목

| 항목 | 한계 |
|---|---|
| 1. 색인 감축률 | **실측치 없음.** 기준값 2.00에 근거가 없어 균등 추출로 처리 |
| 2. 다중 사이트 오버헤드 5.76배 | **국내 조달 사례 1건**에서 도출. 다른 구성에서는 계수가 달라짐 |
| 3. 판정 안정성 문턱값 90% | **근거 문헌 없이 설정.** 80%로 낮추면 권고가 90일에서 60일로 이동 |
| 4. 조달 제약 근거 | 해외 제조사·조사기관 발언. **국내 유통 재고와 납기는 확인하지 못함** |
| 5. 온프레미스 오브젝트 매체 단독 단가 | 시스템 가격만 확보. 매체 비중 불명 |

### 7.3 분석 범위의 한계

**본 분석의 금액은 총소유비용이 아니라 저장 매체 원가입니다.** 3.3절에서 제외한 전력·공간·유지보수·설치 인건비를 포함한 총액은 이보다 큽니다.

또한 **2026년 10월 31일 시행 예정인 접속기록 대상 확대**를 반영하지 않았습니다. 로그량이 증가할 것이나 증가폭을 산정할 근거가 없기 때문입니다. 5년 계산 기간 중 4년 이상이 시행 이후에 해당하므로 실제 소요 용량은 본 분석보다 클 가능성이 있습니다.

| # | 원칙 | 지킨 방식 |

```python
media.get_krw("hdd_manufacturer_realized") + cloud.get("object_price")

```

### 9.2 오류를 검출하는 검증

검증 288건 중 다음은 **정상 동작 확인이 아니라 오류 검출**을 목적으로 작성했습니다.

| 검증 | 실패 조건 |
|---|---|
| 이중 감축 방지 | 압축 상태를 바꿔도 결과가 **같으면** 실패 |
| 미채택 항목 차단 | 미채택 값을 조회했는데 **값이 반환되면** 실패 |
| 단위계 분리 | 두 원장의 값을 더했는데 **예외가 발생하지 않으면** 실패 |
| 명시적 민감도 목록 | 상각기간이 목록에서 **누락되면** 실패 |
| 차트 수치 일치 | 차트값이 엔진 산출값과 **다르면** 실패 |
| 정정 절 존재 | 옛 수치가 본문에 있는데 정정 절이 **없으면** 실패 |

## 11. 재현 방법

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python -m pytest tests/ -q       # 단위 검증 125건
python src/verify_consistency.py # 자기 검증 163건
python src/make_charts.py        # 차트 4장 생성
```

### 구조

```
src/
  placement.py           계층별 논리 용량
  overhead.py            구성 조건별 오버헤드 계수
  reduction.py           감축 적용 → 물리 용량
  pricing_loader.py      가격 원장 로더 (단위계 강제)
  cost_model.py          물리 용량 × 단가
  tco_engine.py          기간별 총비용
  breakeven.py           손익분기 탐색
  sensitivity.py         민감도·불확실성
  make_charts.py         차트 생성
  verify_consistency.py  자기 검증

data/
  media_pricing.yaml     온프레미스 매체 원가 (USD/TB)
  cloud_pricing.yaml     클라우드 이용료 (USD/GB/월)
```

**두 원장을 파일로 분리한 이유**는 단위와 비용 성격이 다르기 때문입니다. 온프레미스는 자본적 지출이고 클라우드는 운영비이며, 클라우드 정가는 NAND 계약가 변동을 즉시 반영하지 않는 반면 매체 구매가는 즉시 반영합니다.
