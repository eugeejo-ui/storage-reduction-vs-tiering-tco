## 3. 발견 1 — 오탐 1건

### 내용

**값은 같고 표기 정밀도만 다릅니다.**

### 처리

**제안서 표기를 바꾸지 않고 스크립트를 고쳤습니다.**

고객 문서에서 소수 둘째 자리까지 쓸 이유가 없습니다. `11.3배`가 읽기 좋습니다. **문서를 코드에 맞추는 것이 아니라 코드가 문서의 정당한 표기를 인정해야 합니다.**

두 표기를 모두 허용하도록 수정하고, 사유를 코드 주석에 남겼습니다.

## 4. 발견 2 — 작업 사본과 저장소의 불일치

### 내용

`phase00_scope.md` 의 완료 기준 6항이 작업 사본과 저장소에서 달랐습니다.

| 위치 | 표기 |
|---|---|
| 저장소 (최신) | 확정 항목 / 검토 후 폐기한 항목 / 폐기 사유 |
| **작업 사본** | **확정한 것 / 검토했다가 버린 것 / 버린 이유** |

이 줄은 **저장소에서 직접 수정**되었고, 그 변경이 작업 사본에 반영되지 않았습니다.

### 왜 문제인가

**이 상태에서 작업 사본을 저장소로 내보내면 이전 수정이 되돌아갑니다.** 값이 틀린 것보다 위험합니다. 고쳤다고 생각한 것이 조용히 원복되기 때문입니다.

### 처리

정정 절을 추가하면서 **작업 사본을 저장소 상태에 맞췄습니다.** 내보내기 전에 반드시 확인해야 하는 항목이며, 아래 5절의 권고에 포함했습니다.

## 5. 발견 3 — 옛 수치 2건과 정정 절 신설

### 내용

`phase00_scope.md` 본문에 이후 단계에서 변경된 값이 남아 있었습니다.

| 위치 | 본문 표기 | 확정값 | 변경 시점 |
|---|---|---|---|
| 3.2절, 6.1절 | 감축 상한 **6.0** | **3.33** | Phase 1 |
| 3절, 6.1절 | 스캔 범위 **4.0 ~ 25.0** | **3.0 ~ 30.0** | Phase 2 |

### 처리 — 본문을 고치지 않았습니다

**19절을 신설해 정정 사실을 기록했습니다.** Phase 6에서 Phase 5를 정정할 때 17절을 신설한 것과 같은 방식입니다.

**본문을 고치지 않는 이유가 중요합니다.**

이 두 값은 **프로젝트의 방향 전환을 만든 값**입니다.

| 값 | 무엇이 바뀌었나 |
|---|---|
| 감축 상한 6.0 → 3.33 | **가설의 전제가 무너지면서 이후 모든 단계의 무게중심이 이동** |
| 스캔 범위 4.0 → 3.0 | 감축 상한 3.33 부근의 전환 구간을 관측하기 위한 확장 |

**본문을 3.33으로 고치면 "처음부터 알고 있었다"가 되어 Phase 1의 발견이 사라집니다.** 착수 시점에 제조사가 제시한 6:1을 상한으로 상정했고, 그것이 도달 불가능함을 확인한 것이 성과입니다.

### 다만 그대로 두지도 않았습니다

`phase00` 만 읽는 사람은 4.0~25.0을 최종값으로 오해합니다. 19.3절에 **각 항목의 확정값이 어느 문서에 있는지** 안내표를 넣었습니다.

## 6. 신설한 검사 2종

### 6.1 미확정 항목 전파 검사

**읽는 사람이 지적해서 드러난 유형을 자동화했습니다.**

작업 기록에 기록된 한계가 고객 문서에도 나타나는지 대조합니다.

| 규칙 | 작업 기록 | 고객 문서 |
|---|---|---|
| 색인 감축률 근거 부재 | phase01, phase06 | phase08, README |
| **다중 사이트 계수의 사례 1건** | phase02, phase07 | phase08, README |
| 판정 문턱값 90%의 자의성 | phase06, phase07 | phase08, README |
| 국내 유통 재고 미확인 | phase07 | phase08, README |
| 총소유비용이 아니라 매체 원가 | phase00, phase04 | phase08, README |

**두 번째 규칙이 실제로 누락되었던 항목입니다.** 다중 사이트 계수 5.76이 조달 사례 1건에서 나왔다는 사실이 작업 기록에는 있었으나 제안서에는 없었습니다.

**출처에도 없으면 경고를 냅니다.** 규칙 자체가 낡았을 수 있기 때문입니다.

### 6.2 옛 수치와 정정 절 검사

**본문에 옛 표기가 있으면 정정 절이 있어야 통과합니다.**

```
phase00 에 "4.0 ~ 25.0" 이 있으면
  → 정정 절과 확정값 "3.0 ~ 30.0" 이 함께 있어야 통과
  → 없으면 오류
```

**역검증했습니다.** 정정 절을 제거한 사본으로 실행하니 오류 2건이 정확히 검출되었습니다.

```
오류 — 옛 표기 '4.0 ~ 25.0' 이 본문에 있는데 정정 절이 없습니다
오류 — 옛 표기 '1.0(감축 없음) ~ 6.0' 이 본문에 있는데 정정 절이 없습니다
```

**앞으로 값이 또 바뀌어도 기록 없이 넘어가지 않습니다.**
