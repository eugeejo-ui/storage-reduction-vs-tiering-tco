# 플래시 대비 계층화 저장 설계 — 총소유비용 비교 분석

> **접속기록 2년 보관 의무가 있는 환경에서, 보안 로그 저장 비용을 어떻게 줄일 것인가.**
> 데이터 감축과 계층화 중 어디에 투자해야 하는지를 판단하는 계산 도구입니다.

플래시와 대체 계층의 단가 격차가 4.9배에서 22.6배로 벌어진 시장 조건에서 출발했습니다. 결론은 **격차와 무관했습니다.**

---

## 핵심 결과

### 1. 계층화의 이득은 단가 격차가 아니라 색인 제거에서 나옵니다

착수 시 가설은 "단가 격차가 커지면 계층화가 유리해진다"였습니다. **부분 반증되었습니다.**

| 단가 격차 | 전량 고성능 | 최대 계층화 |
|---|---|---|
| **1배 (동일 단가)** | 1.23백만원 | **0.49백만원** |
| 22배 (현재 시장) | 89.3백만원 | 1.8백만원 |

**단가가 같아도 계층화가 유리합니다.** 아카이브 계층은 검색 색인이 제거되어 저장 계수가 0.50에서 0.15로 떨어지기 때문입니다. 격차가 벌어진 것은 이득을 키웠을 뿐입니다.

### 2. 제조사 감축 보증 6:1은 이 워크로드에서 물리적으로 도달할 수 없습니다

제조사 약관 원문을 확보해 확인했습니다.

> Unreducible Data의 예에는 **호스트에서 압축된 데이터**가 포함된다.

로그 원본은 이미 압축된 상태로 저장 장비에 도달합니다. 계약상 보증 대상이 아닙니다.

```
혼합 감축률 = 0.50 / (0.15 + 0.35 / d)
→ 색인이 0바이트가 되는 물리적 불가능 경우에도 3.33이 상한
```

### 3. 점 추정값의 크기가 판정의 확실성을 보장하지 않습니다

3개 사이트 분산 요건을 수용할 수 있는지 판정한 결과입니다.

| 즉시검색 기간 | 필요 단가 격차 | 시장(22배)과의 차이 | **수용 가능 확률** |
|---|---|---|---|
| 30일 | 33.84배 | 54% 초과 | **51%** |
| 60일 | 16.84배 | 24% 여유 | 87% |
| 90일 | 11.30배 | 49% 여유 | **100%** |

**30일 기준은 임계값이 시장 배수를 54% 웃돌아 판정이 확실해 보이지만, 임계값 자체가 10.8에서 50.1 사이에서 흔들립니다. 중앙값은 19.3으로 시장 배수보다 낮습니다.**

## 그 밖에 확인된 것

| # | 발견 |
|---|---|
| 1 | **혼합 감축률 1.538과 블록 RAID 오버헤드 1.536이 거의 정확히 상쇄됩니다.** 서로 다른 두 출처에서 독립적으로 나온 값입니다 |
| 2 | 어레이 제조사 정품 드라이브는 원시 매체 시세의 **2.8~3.9배**입니다 |
| 3 | 시장 지수의 디스크 계열이 제조사 SEC 공시와 모순됩니다 (+146% 대 +2.6%) |
| 4 | 다중 사이트 구성에서 계층화가 **물리 용량을 오히려 늘립니다.** 다만 비용은 줄어듭니다 |
| 5 | **최적화가 대응 여력을 소진합니다.** 계층화를 이미 많이 한 조직일수록 가용성 요건 추가를 감당하기 어렵습니다 |

## 어떻게 확인했는가

### 예측하지 않았습니다

가격 지수가 같은 분기에 대해 **세 가지 배수(16.4·22.6·23.2)를 동시에 발표**하고 있고, 자사 과거 수치를 60% 상향 개정한 이력이 있습니다.

특정 값을 고르는 대신 **단가 격차를 3배에서 30배까지 훑었습니다.** 어느 지수를 믿든 결론이 달라지지 않도록 설계했습니다.

### 1차 자료로 검증했습니다

| 자료 | 확인 내용 |
|---|---|
| **제조사 감축 보증 약관 원문** | 호스트 압축 데이터 제외 명시 |
| **Seagate Form 10-Q** | 출하 엑사바이트 공시에서 TB당 실현 단가 직접 도출 |
| **국가종합전자조달시스템 4건** | 금액과 용량이 함께 명시된 국내 실거래가 |
| **법인세법 시행규칙 별표 5** | 교체 주기 4~6년 |

**시장 지수의 디스크 단가는 제조사 재무제표와 모순되어 채택하지 않았습니다.** 코드가 이를 강제합니다.

### 독립 경로로 교차검증했습니다

소매 매체가 × 단가 격차(22) × 정품 프리미엄(3.3) = **2,450,976원/TB**
국내 조달 낙찰가에서 역산한 값 = **2,856,538원/TB**

전혀 다른 두 경로가 **14% 차이**로 맞아떨어졌습니다.

## 재현 방법

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt

python -m pytest tests/ -q       # 검증 124개
python src/make_charts.py        # 차트 4장 생성
```

### 구조

```
src/
  placement.py       계층별 논리 용량
  overhead.py        구성 조건별 오버헤드 계수
  reduction.py       감축 적용 → 물리 용량
  pricing_loader.py  가격 원장 로더
  cost_model.py      물리 용량 × 단가
  tco_engine.py      기간별 총비용
  breakeven.py       손익분기 탐색
  sensitivity.py     민감도·불확실성
  make_charts.py     차트 생성

data/
  media_pricing.yaml  온프레미스 매체 원가 (USD/TB)
  cloud_pricing.yaml  클라우드 이용료 (USD/GB/월)
```

**두 원장을 파일로 분리한 이유**는 단위와 비용 성격이 다르기 때문입니다. 값을 실수가 아니라 단위와 출처를 지닌 객체로 반환해 **합산을 구조적으로 차단**했습니다.

```python
media.get_krw("hdd_manufacturer_realized") + cloud.get("object_price")
# UnitSystemError: 단위계가 다른 값을 연산할 수 없습니다
```

### 오류를 막는 검증

검증 124개 중 다음은 **정상 동작 확인이 아니라 오류 검출**을 목적으로 합니다.

| 검증 | 실패 조건 |
|---|---|
| 이중 감축 방지 | 압축 상태를 바꿔도 결과가 **같으면** 실패 |
| 미채택 항목 차단 | 미채택 값을 꺼냈는데 **값이 나오면** 실패 |
| 단위계 분리 | 두 원장 값을 더했는데 **예외가 안 나면** 실패 |
| 명시적 민감도 목록 | 상각기간이 목록에서 **빠지면** 실패 |
| 차트 수치 일치 | 차트값이 엔진값과 **다르면** 실패 |

**근거가 약한 항목도 밝힙니다.**

| 항목 | 한계 |
|---|---|
| 색인 감축률 | 실측치 없음. 범위 1.0~6.0으로 균등 추출 |
| 다중 사이트 오버헤드 5.76 | **국내 조달 사례 1건**에서 도출 |
| 판정 안정성 문턱값 90% | **근거 문헌 없이 설정.** 80%로 낮추면 권고가 90일에서 60일로 이동 |
